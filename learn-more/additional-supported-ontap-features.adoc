= Funzionalità ONTAP comuni supportate sui sistemi ASA r2
:allow-uri-read: 
:icons: font
:imagesdir: ../media/


[role="lead"]
Poiché i sistemi ASA r2 utilizzano una versione semplificata di ONTAP, esegui molte attività comuni di ONTAP e funzioni di System Manager nello stesso modo degli altri sistemi ONTAP.

Per ulteriori informazioni sulle caratteristiche e funzioni comuni, consultare la seguente documentazione ONTAP .



[[autosupport]]
== AutoSupport

A partire da ONTAP 9.20.1, System Manager visualizza avvisi AutoSupport se AutoSupport è configurato per il protocollo SMTP anziché per il protocollo HTTPS, se AutoSupport è disabilitato ma i destinatari e-mail di clienti e partner rimangono configurati e se una trasmissione AutoSupport non riesce a causa di un problema DNS.

link:https://docs.netapp.com/us-en/ontap/system-admin/manage-autosupport-concept.html["Scopri di più su AutoSupport"^].



[[data-protection]]
== Protezione dei dati

Scopri di più sulle comuni funzionalità di protezione dei dati supportate sui sistemi ASA r2.



[[clustered-external-key-servers]]
=== Server di chiavi esterne in cluster

Puoi configurare la connettività a server di gestione delle chiavi esterni in cluster su una storage VM. Con i server di chiavi in cluster, puoi designare server di chiavi primari e secondari su una storage VM. Quando registri le chiavi, ONTAP prova prima con un server di chiavi primario e poi, in sequenza, con i server secondari fino a quando l'operazione riesce, evitando chiavi duplicate.

link:https://docs.netapp.com/us-en/ontap/encryption-at-rest/configure-cluster-key-server-task.html["Impara a configurare server di chiavi esterne in cluster"^].



[[external-key-management-for-encryption-at-rest]]
=== Gestione delle chiavi esterne per la crittografia a riposo

È possibile utilizzare uno o più server KMIP per proteggere le chiavi utilizzate dal cluster per accedere ai dati crittografati.

A partire da ONTAP 9.20.1, quando abiliti un gestore di chiavi esterno su una VM di storage dei dati, ONTAP migra automaticamente le chiavi di crittografia del volume di quella VM di storage dal key manager con ambito admin al nuovo key manager della VM di storage dei dati. Questo semplifica il passaggio alla gestione delle chiavi esterna ed elimina la necessità di una fase separata di migrazione manuale nel flusso di lavoro standard.

* link:https://docs.netapp.com/us-en/ontap/encryption-at-rest/enable-external-key-management-96-later-hw-task.html["Abilita la gestione delle chiavi esterne"^].
* link:https://docs.netapp.com/us-en/ontap/encryption-at-rest/enable-external-key-management-96-later-nve-task.html["Abilita la gestione delle chiavi esterne (NVE)"^] .

[[administrator-access-management]]
=== Gestione degli accessi dell'amministratore

Il ruolo assegnato a un amministratore determina quali funzioni può svolgere. System Manager offre ruoli predefiniti per gli amministratori del cluster e per gli amministratori delle VM di storage. Assegni il ruolo quando crei l'account dell'amministratore oppure puoi assegnare un ruolo diverso in un secondo momento.

link:https://docs.netapp.com/us-en/ontap/task_security_administrator_access.html["Impara a gestire l'accesso dell'amministratore con System Manager"^].



[[client-authentication-and-authorization]]
=== Autenticazione e autorizzazione del client

ONTAP utilizza metodi standard per proteggere l'accesso dei client e degli amministratori allo storage e per proteggerli dai virus.  Sono disponibili tecnologie avanzate per la crittografia dei dati a riposo e per l'archiviazione WORM.  ONTAP autentica un computer client e un utente verificandone l'identità con una fonte attendibile.  ONTAP autorizza un utente ad accedere a un file o a una directory confrontando le credenziali dell'utente con le autorizzazioni configurate sul file o sulla directory.

link:https://docs.netapp.com/us-en/ontap/concepts/client-access-storage-concept.html["Scopri di più sull'autenticazione e l'autorizzazione del client"^] .



[[fc-sp-3-authentication-and-encryption]]
=== Autenticazione e crittografia FC-SP-3

A partire da ONTAP 9.20.1, ONTAP supporta l'autenticazione e la crittografia Fibre Channel Security Protocol 3 (FC-SP-3) su HBA sicuri Broadcom con sistemi ASA r2. Il supporto FC-SP-3 consente la crittografia end-to-end a livello hardware e l'autenticazione dei dispositivi per proteggere i dati in transito tra gli host SAN FC e NVMe/FC e i sistemi storage ONTAP, in conformità con gli standard di sicurezza Fibre Channel T11.

* link:https://docs.netapp.com/us-en/ontap/san-admin/fc-sp-3-security-support.html["Scopri di più sull'autenticazione e la crittografia FC-SP-3"^].




[[multi-admin-verification-mav]]
=== Verifica multi-amministratore (MAV)

A partire da ONTAP 9.20.1, i gruppi di approvazione MAV possono includere come approvatori gruppi di identity provider (IdP), Active Directory (AD) e LDAP (nsswitch), oltre ai singoli amministratori. I tipi di gruppo supportati includono Entra ID, ADFS, gruppi di dominio AD e gruppi LDAP. L'aggiunta o la rimozione di utenti nella directory IdP, AD o LDAP non richiede alcuna modifica alla configurazione MAV. link:https://docs.netapp.com/us-en/ontap/multi-admin-verify/index.html["Scopri di più su MAV"^].



[[oauth-2-0-authentication]]
=== Autenticazione OAuth 2.0

È possibile utilizzare il framework Open Authorization (OAuth 2.0) per controllare l'accesso ai cluster ONTAP .  OAuth 2.0 limita e controlla l'accesso alle risorse protette mediante token di accesso firmati.

link:https://docs.netapp.com/us-en/ontap/authentication/overview-oauth2.html["Scopri di più sull'autenticazione OAuth 2.0"^] .



[[saml-authentication-and-administrator-access]]
=== Autenticazione SAML e accesso amministratore

È possibile configurare e abilitare l'autenticazione Security Assertion Markup Language (SAML) per i servizi Web.  SAML autentica gli utenti tramite un Identity Provider (IdP) esterno anziché tramite provider di servizi di directory come Active Directory e LDAP.

link:https://docs.netapp.com/us-en/ontap/system-admin/configure-saml-authentication-task.html["Impara a configurare l'autenticazione SAML"^].



[[snmp]]
=== SNMP

A partire da ONTAP 9.20.1, ONTAP supporta l'autenticazione SHA-512 per gli utenti SNMPv3. Questo miglioramento ti consente di utilizzare un'autenticazione SNMPv3 più sicura per i client SNMP esterni e per il monitoraggio degli switch, inclusi quelli che richiedono l'autenticazione SHA-512.

* link:https://docs.netapp.com/us-en/ontap/networking/configure_snmpv3_users_in_a_cluster.html["Impara a configurare gli utenti SNMPv3"^].
* link:https://docs.netapp.com/us-en/ontap-systems-switches/switch-cshm/config-snmpv3.html["Impara a configurare SNMPv3 sugli switch"^].




[[tls-hardware-offload]]
=== Offload TLS hardware

È possibile delegare la crittografia e la decrittografia Transport Layer Security (TLS) dell'intero cluster alle schede Ethernet supportate. Ciò riduce il carico sulla CPU e migliora le prestazioni dei sistemi che utilizzano TLS.

link:https://docs.netapp.com/us-en/ontap/networking/configure-tls-offload.html["Impara a configurare l'offload hardware TLS"^].

[[fips-compliance]]
=== Conformità FIPS

ONTAP è conforme agli standard federali di elaborazione delle informazioni (FIPS) 140-2 per tutte le connessioni SSL. Puoi attivare e disattivare la modalità SSL FIPS, impostare i protocolli SSL a livello globale e disattivare eventuali algoritmi di crittografia deboli come RC4 all'interno di ONTAP.

A partire da ONTAP 9.18.1, gli algoritmi crittografici di elaborazione postquantistica sono supportati per SSL.  Questi algoritmi forniscono una protezione aggiuntiva contro potenziali futuri attacchi al computer quantistico e sono disponibili quando la modalità SSL FIPS è disabilitata.

* link:https://docs.netapp.com/us-en/ontap/networking/configure_network_security_using_federal_information_processing_standards_fips.html["Impara a configurare FIPS per tutte le connessioni SSL"^].




[[link-aggregation-groups-lags]]
=== Gruppi di aggregazione di link (LAG)

Un gruppo di interfacce, noto anche come Link Aggregation Group (LAG), viene creato combinando due o più porte fisiche sullo stesso nodo in un'unica porta logica.  La porta logica garantisce maggiore resilienza, maggiore disponibilità e condivisione del carico.

link:https://docs.netapp.com/us-en/ontap/networking/combine_physical_ports_to_create_interface_groups.html["Scopri di più sui gruppi di aggregazione dei link"^].

== Prestazioni

Scopri di più sulle funzionalità prestazionali più comuni supportate sui sistemi ASA r2.



[[modify-default-settings-that-control-automatic-qos-throughput-ceiling-increases]]
=== Modifica le impostazioni predefinite che controllano gli aumenti automatici del limite massimo di throughput QoS

I gruppi di criteri QoS adattivi e non adattivi aumentano temporaneamente del 50% il throughput massimo di un carico di lavoro per 1 secondo, per impostazione predefinita, per rispondere alle richieste a breve termine di prestazioni superiori. A partire da ONTAP 9.19.1, puoi modificare queste impostazioni. In ONTAP 9.18.1 e versioni precedenti, non puoi modificarle.

link:https://docs.netapp.com/us-en/ontap/performance-admin/guarantee-throughput-qos-task.html["Scopri di più sui limiti di throughput QoS"^].



[[ipspace-tcp-performance]]
=== Prestazioni TCP nello spazio IP

A partire da ONTAP 9.19.1, ONTAP migliora le prestazioni del trasferimento dati TCP su collegamenti WAN con perdita di pacchetti e latenza elevata, integrando due funzionalità di recupero delle perdite, PRR e RACK, nello stack TCP di ONTAP. PRR è adatto a tutte le reti ed è abilitato per impostazione predefinita. RACK è adatto a reti congestionate con velocità di collegamento di circa 25 Gigabit/secondo ed è disabilitato per impostazione predefinita.

link:https://docs.netapp.com/us-en/ontap/networking/improve-tcp-wan-performance.html["Scopri di più su come migliorare le prestazioni TCP WAN con PRR e RACK"^].



[[san-configuration]]
== Configurazione SAN

Una rete di archiviazione (SAN) è costituita da una soluzione storage connessa agli host tramite un protocollo di trasporto SAN come iSCSI o FC. È possibile configurare la SAN in modo che la soluzione storage si connetta agli host tramite uno o più switch. Se si utilizza iSCSI, è anche possibile configurare la SAN in modo che la soluzione storage si connetta direttamente all'host senza utilizzare uno switch.



[[san-direct-attachment]]
=== Attacco diretto SAN

A partire da ONTAP 9.19.1, non è necessario uno switch FC per stabilire connessioni tra host FC e FC-NVMe e storage ONTAP. Gli host possono essere collegati direttamente alle porte dell'adattatore FC sui sistemi ASA r2. La possibilità di collegamento diretto può essere particolarmente utile in siti remoti e ambienti ibridi dove la semplicità è fondamentale.

* link:https://docs.netapp.com/us-en/ontap/san-config/configure-fc-nvme-hosts-ha-pairs-reference.html#direct-attach-fc-and-fc-nvme-configurations["Scopri di più sull'attacco diretto SAN"^].




[[san-protocols]]
== Protocolli SAN

I sistemi ASA r2 supportano tutti i protocolli SAN (iSCSI, FC, NVMe/FC, NVMe/TCP).

* link:https://docs.netapp.com/us-en/ontap/san-admin/san-host-provisioning-concept.html["Scopri di più sul protocollo iSCSI"^].
* link:https://docs.netapp.com/us-en/ontap/san-admin/san-provisioning-fc-concept.html["Scopri di più sul protocollo Fibre Channel (FC)"^].
* link:https://docs.netapp.com/us-en/ontap/concept_nvme_provision_overview.html["Scopri di più sul protocollo NVMe"^].
+
** link:https://docs.netapp.com/us-en/ontap/san-admin/nvme-copy-offload.html["Impara a configurare l'offload della copia NVMe"^].
+
A partire da ONTAP 9.18.1, ONTAP supporta l'offload di copia NVMe. L'offload di copia NVMe consente a un host NVMe di delegare le operazioni di copia dalla propria CPU alla CPU dello storage controller ONTAP. L'host può copiare i dati da un namespace NVMe a un altro, riservando al contempo le risorse della CPU per i carichi di lavoro delle applicazioni.

** link:https://docs.netapp.com/us-en/ontap/san-admin/enable-space-allocation.html["Scopri di più sull'allocazione dello spazio (unmap) per NVMe"^].
+
A partire da ONTAP 9.16.1, la deallocazione dello spazio (detta anche "hole punching" e "unmap") è abilitata per impostazione predefinita per gli spazi dei nomi NVMe. La deallocazione dello spazio consente a un host di deallocare blocchi non utilizzati dagli spazi dei nomi per recuperare spazio.







[[storage-efficiency]]
== Efficienza dello storage

L'efficienza di archiviazione è la misura di quanto efficacemente un sistema storage utilizzi lo spazio disponibile, ottimizzando le risorse di storage, minimizzando lo spazio sprecato e riducendo l'ingombro fisico dei dati scritti.

ONTAP offre diverse tecnologie per l'efficienza dello storage che possono aiutarti a ottimizzare l'utilizzo dello storage e a ridurre i costi.

link:https://docs.netapp.com/us-en/ontap/concepts/storage-efficiency-overview.html["Scopri di più sulle tecnologie di efficienza dello storage ONTAP"].



[[data-reduction-rate-drr]]
=== Tasso di riduzione dei dati (DRR)

A partire da ONTAP 9.20.1, il tasso di riduzione dei dati (DRR) dell'efficienza dello storage fornisce una valutazione più precisa del risparmio di spazio dell'efficienza dello storage di ONTAP, includendo solo i dati riducibili. In ONTAP 9.19.1 e versioni precedenti, il DRR include sia i dati riducibili sia quelli non riducibili.

link:https://docs.netapp.com/us-en/ontap/concepts/capacity-measurements.html["Scopri di più su come ONTAP segnala lo spazio di storage utilizzato"^].



[[global-deduplication]]
=== Deduplicazione globale

A partire da ONTAP 9.19.1, la deduplicazione globale estende la link:https://docs.netapp.com/us-en/ontap/concepts/deduplication-concept.html["Risparmio di spazio derivante dalla deduplicazione ONTAP esistente"^] a livello di unità di storage all'intera zona di disponibilità dello storage (SAZ). Eliminando i blocchi di dati duplicati in tutte le unità di storage della SAZ, puoi migliorare significativamente l'efficienza dello storage e ridurre il costo totale di proprietà. La deduplicazione globale non richiede alcuna licenza della funzionalità, è abilitata per impostazione predefinita, si integra perfettamente con le tecnologie di efficienza dello storage esistenti e opera in modo trasparente con un impatto minimo sulle prestazioni e senza richiedere configurazione amministrativa.

[[user-password-expiration-alerts]]
=== Avvisi di scadenza della password utente

A partire da ONTAP 9.20.1, se il ruolo associato a un account utente è configurato per gli avvisi di scadenza della password, l'utente riceve un avviso banner nella parte superiore della pagina di System Manager immediatamente dopo l'accesso, a partire da 14 giorni prima della scadenza della password. L'avviso si aggiorna ogni volta che l'utente accede per mostrare il numero di giorni rimanenti fino alla scadenza della password. Puoi configurare gli avvisi di scadenza quando aggiungi o modifichi un ruolo di amministratore.

link:https://docs.netapp.com/us-en/ontap/authentication/configure-password-expiry-alerts.html["Scopri come configurare gli avvisi di scadenza della password in System Manager"^].
